# Cockpit (leitstand, Stufe 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jede Sitzung meldet ihren Status in eine eigene JSON-Datei; `/cockpit` öffnet ein Fenster, das alle Dateien alle 5 s liest und Zahlen plus sortierte Liste zeigt.

**Architecture:** Gleiches Plugin wie Stufe 1. Melder (`reporter.ts`) hängt an `session.start`, `turn.start`, `turn.complete`, `tool.call`, `session.end` und `/modus` und schreibt per `$.fs.write`. Rechenlogik rein in `board.ts`. `register.tsx` verdrahtet, registriert `/cockpit` und zeichnet das Pane; ein `$.clock.every`-Takt legt die gelesenen Dateien in `$.state`, das Pane liest sie beim Zeichnen.

**Tech Stack:** TypeScript/TSX gegen `claude-code` (Build 2.1.304), Tests mit `claude-code/testing` über `claude plugin test`.

**Spec:** `docs/superpowers/specs/2026-10-21-cockpit-design.md`

**API-Referenz:** Typen unter `.claude-plugin/types/claude-code/index.d.ts` im Repo (oder die vom Skill `plugin-authoring` frisch geschriebene `types/claude-code.d.ts`); grep nach `'fs.write'`, `'clock.every'`, `'agent.list'`, `'env.get'`, `TurnCompleteInput`, `AgentInfo`. Beispiele im Skill-Ordner `examples/` (`pane.tsx`, `pane.test.tsx`). `claude` liegt nicht im PATH: `C="$HOME/Library/Application Support/Claude/claude-code/2.1.304/6bbba6adc37f/claude.app/Contents/MacOS/claude"` (Pfad bei Bedarf mit `ls` prüfen).

## Global Constraints

- Datei je Sitzung: `${HOME}/.claude/leitstand/<sessionId>.json`, `HOME` aus `$.env.get("HOME")`; fehlt `HOME`, schreibt der Melder nichts.
- Dateiinhalt exakt: `{ v: 1, sessionId, title, project, cwd, status, waitingFor, mode, agents, updatedAt }`.
- `status` ∈ `arbeitend` | `wartet` | `bereit` | `beendet`; `waitingFor` ∈ `"Rückfrage"` | `"Plan"` | `null`.
- Titel: erster Satz der ersten nicht leeren Nachricht der Hauptschleife, höchstens 60 Zeichen inkl. „…“.
- Lebenszeichen bei sonstigen `tool.call`s höchstens alle 30 s schreiben.
- Cockpit-Takt 5 s; „unklar“ = `arbeitend` und älter als 10 Min; ausgeblendet = `beendet` oder älter als 24 h.
- Werkzeugnamen: `AskUserQuestion`, `ExitPlanMode`, `mcp__ccd_turn__wrap_up` (wrap_up zählt nur mit nicht leerem `ask`).
- Die Sitzung darf nie an der Mod scheitern: jeder Melder-Fehler wird verschluckt, `next(e)` läuft immer.
- Pane-ID `cockpit`, Titel „Cockpit“, Befehl `cockpit`.
- Stufe 1 (`modes.ts`, `/modus`, `prompt.submit`) bleibt im Verhalten unverändert; ihre Tests bleiben grün.
- Texte deutsch, keine Gedankenstriche (—) in sichtbaren Texten.

## Review Focus

1. Rückfrage in einem **Unteragenten** (`tool.call` mit `agentId`) darf die Sitzung nicht auf `wartet` setzen → Test in Task 3.
2. `turn.start` mit leerem Text (Fortsetzung) überschreibt keinen Titel und setzt keinen leeren → Test in Task 3.
3. AskUserQuestion wird abgelehnt oder wirft (`next` wirft) → Status trotzdem zurück auf `arbeitend` → Test in Task 3.
4. Datei einer **fremden Version** (`v: 2`) oder halb geschrieben (abgeschnittenes JSON) → übersprungen, Rest sichtbar → Test in Task 2.
5. Pane wird geschlossen → Takt stoppt, kein weiteres `fs.list` → Test in Task 4.
